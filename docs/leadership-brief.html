Giving our AI assistants secure access to archived email

A way for approved AI assistants to search employees' archived mailboxes — including executives' large auto-expanding archives — with each person able to see only their own email.

July 21 – August 14, 2026 Updated: 14 Aug 2026 Status: in use, hardened; rollout items remain
✓

Bottom line — it works today

Archived-email search functions end to end for every mailbox type, confirmed against a real message the standard tools couldn't reach. What remains is hardening and rollout, not core capability.

How we got here

  1. Security review & cloud tidy-up Done

    Worked through a 49-item security checklist and closed the gaps, then consolidated a key security vault and removed leftover test resources — with no interruption to the running service.

  2. Connected the assistant Done

    Cleared a series of Microsoft sign-in configuration hurdles so a user can connect and be authenticated as themselves.

  3. A major roadblock — and it wasn't ours Turning point

    We found that Microsoft's standard programming interface simply cannot read the archive mailbox — a capability Microsoft hasn't shipped yet. We proved this thoroughly rather than assume it, so no effort was wasted chasing a dead end.

  4. Found a compliant path that works Done

    Routed archive access through Microsoft Purview eDiscovery — the supported, enterprise service that can reach archives, including the executives' large ones — with each user's searches fully walled off in their own case. Verified live by retrieving a 2022 email thread the standard interface couldn't touch.

  5. Added an "open in Outlook" convenience In progress

    Built a helper that opens a search result as the real message in desktop Outlook. It needs a one-time Microsoft code-signing certificate (a few-day identity-verification step) before firm-wide rollout.

  6. Organized & backed up the work Done

    Cleaned the project, confirmed no secrets were exposed, and published it to a private repository.

  7. Fixed a "hangs and returns nothing" issue Done

    A reported freeze traced to Microsoft's archive export now taking ~50 seconds while our tool waited too long in one step. The tool now responds quickly and checks back in the background instead of hanging.

  8. Diagnosed and fixed a service outage Done

    A colleague reported the assistant had stopped working. The cause was outside our code: Microsoft shipped a new preview version of a platform component, and our configuration had been set to accept new versions automatically — so a routine restart silently adopted a broken one. We pinned the known-good version, and the service came back immediately. Nothing like it can recur without a deliberate change on our side.

  9. Made the service instantly available Done

    The service had been shutting itself down when idle to save cost, and the first person to use it each morning waited long enough that their connection gave up. One instance now stays warm at all times, for a small ongoing cost.

  10. Tightened permissions & opened self-service access Done

    Audited every permission the system holds against what the code actually uses, removed a redundant one, required explicit assignment to sign in, and closed a stale sign-in path. Staff who need access now request it themselves and are approved — instead of hitting an error with no route forward.

  11. Fixed the audit trail Done

    Investigating the outage revealed that our per-call audit records were losing the caller's identity before reaching the log. Corrected and verified: every tool call is now attributable to a named person.

  12. Silenced our own false alarms Done

    Every archive search this system runs is, to the security tooling, an eDiscovery search — the same activity it is designed to alert on. Those routine alerts are now suppressed for this system specifically, so genuine eDiscovery activity elsewhere still raises a flag.

  13. Built a searchable archive index Done

    Stood up a shared, always-available database so archive searches can be answered instantly from an index instead of re-querying Microsoft each time. It holds only metadata — subject, sender, date, folder — never message content. Built to host the data for future assistants too, not just this one.

Where things stand

Remaining before we call it 1.0

  • Complete the Microsoft code-signing certificate so the Outlook convenience can roll out firm-wide.
  • Move server ownership from an individual to a group, so it survives staffing changes.
  • Final security review.

Setbacks — understood & handled

  • Workstation security tooling blocked some routine network and sign-in operations; every step was adapted around it.
  • A Microsoft product limitation forced the shift to eDiscovery — now a strength, since it also covers auto-expanding archives.
  • Sign-in sessions expired mid-work; all cloud actions now run as operator-run scripts with a safeguard against unattended access.
  • A platform component auto-updated itself into an outage. Version now pinned; the same class of surprise is closed off.
  • Connection failures at the front door leave no trace in our logs, so the first investigation was slower than it should have been. Purpose-built diagnostic scripts now cover that blind spot.
